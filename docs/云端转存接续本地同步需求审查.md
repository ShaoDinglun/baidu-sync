# 云端成功后接续本地同步：候选链路审查

已确认：基金云端21:08才获得当日ETF/LOF，而本地同步21:00已结束；相同错误也可发生在23点最后一轮。当前固定两份已完成隔离下载、全ZIP CRC及NFS SHA核验，旧文件未覆盖，原日更已按既有直接修复授权续跑。

本次属于链路改动。现有流程为云端定时转存与本地定时下载分别执行，再由52唯一小时日更验收。候选保持原定时兜底，新增成功转存后的匹配本地同步请求，并以一分钟内部检查恢复持久请求；它不启动另一日更任务，不更改原cron或凭证。

匹配只接受相同规范化远端根、已启用且自动运行的本地任务。状态只保存任务ID、根、事件摘要与序号；不得保存分享链接、提取码、Cookie或OAuth值。重复事件去重，新事件合并；执行中产生的新请求不能被旧结果清除。忙或失败保留并限频重试，重启可恢复；取消、禁用、根变更不能误触发。破损状态保留并报错，不能当空状态重置。

复用现有增量下载器和锁，不修改市场数据口径、覆盖策略、通知配置或实盘。源任务成功与本地数据到位仍分别验收；本地同步失败不能伪称数据可用。生产只在完整候选验收和当前日更自然空闲后切换，旧代码及配置保留回滚，不合主分支。

默认重试间隔60秒，仅作用于既有采集应用内的接续队列；它不改变52的唯一小时定时器。外部分享长期未发布或不可访问仍是外部依赖，不能伪造数据来宣称05点前完整发布；需继续核实恢复与日更全链路耗时。

验证顺序：先执行缺模块红测，再实现普通、空/坏事件、重复、执行中更新、忙/网络失败、禁用/换根、重启、损坏状态和跨实例并发用例；然后验证真实调度入口接线、真实隔离下载调用、当前版本兼容及没有敏感日志。此处尚未改生产。

- 云端转存成功或无新增文件时，发送四字段完成事件；不会转交分享链接、提取码或认证。
- 复用现有本地单线程 APScheduler，每60秒核对待办与最后完成的转存状态；原17至23点cron保留。
- 接续调用既有同步器，background=False，沿用现有下载运行锁、覆盖策略和任务配置。任务忙或失败保留待办，跨午夜继续重试；新转存事件不会被执行中的旧任务清除。
- 同一来源完成时间的int/float表示保持去重；队列状态写入异常明确记录，不能误报为已有下载运行。
- 35项隔离测试通过。生产依赖验收入口 tests/production_dependency_acceptance.py 使用现有Python环境，阻止真实网络、mock认证初始化/消息/下载，检验实际模块加载、APScheduler启动、原cron保留和应用接线，并包含35项候选及3项既有存储重试回归。

- 未承诺上游缺失仍能生成数据；05点发布目标仍需后续完整自然日更证据。
